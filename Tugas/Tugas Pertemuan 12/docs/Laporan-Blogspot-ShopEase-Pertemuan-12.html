1.2 Membuat database MySQL untuk praktikum

Masuk ke MySQL menggunakan akun lokal yang boleh membuat database, misalnya melalui mysql -u root -p. Jalankan SQL berikut untuk instalasi baru. Ganti contoh kata sandi dengan nilai lokal Anda dan gunakan nilai yang sama pada file konfigurasi.

CREATE DATABASE IF NOT EXISTS db_shopease
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'shopease'@'127.0.0.1'
  IDENTIFIED BY 'GantiDenganPasswordLokal';
GRANT ALL PRIVILEGES ON db_shopease.*
  TO 'shopease'@'127.0.0.1';

Dari folder tugas, salin shopease/env menjadi shopease/.env pada checkout baru. Jika file sudah ada, buka file itu dan sesuaikan nilainya.

CI_ENVIRONMENT = development
app.baseURL = 'http://localhost:8080/'
database.default.DBDriver = MySQLi
database.default.hostname = 127.0.0.1
database.default.port = 3306
database.default.database = db_shopease
database.default.username = shopease

Untuk mencoba aplikasi secara ringan pada checkout baru tanpa menyiapkan layanan MySQL, jalankan bash scripts/setup.sh sqlite dari folder tugas, lalu cd shopease dan php spark serve. Pada mode ini data tersimpan di writable/db_shopease.sqlite. Saat berpindah database, ubah .env terlebih dahulu dan jalankan setup untuk driver tujuan.

2. Merancang relasi data dan mengisi katalog awal

Saya mempertahankan tabel pengguna dari praktikum autentikasi. Modul ini menambahkan tiga tabel. Setiap produk harus menunjuk kategori yang ada. Satu produk dapat memiliki beberapa gambar. Nama file disimpan di database dan berkas gambarnya disimpan di direktori unggahan.

Relasi Jika induk dihapus Dampak pada aplikasi
products.id_category → categories.id_category RESTRICT Aplikasi meminta pengguna memindahkan atau menghapus produk sebelum menghapus kategorinya.
product_images.id_product → products.id_product CASCADE MySQL menghapus baris gambar yang terkait. Setelah transaksi berhasil, aplikasi membersihkan file fisiknya.

Kedua relasi menggunakan ON UPDATE CASCADE. Harga memakai DECIMAL(12,2) agar pecahan rupiah tetap tersimpan. Status penayangan menerima tersedia atau tidak_tersedia. Kolom stock menyimpan jumlah unit. Produk yang stoknya nol tetap dapat dicatat.

Seeder menambahkan kategori Fashion, Elektronik, Olahraga, dan Gaya Hidup. Dua data awal mengikuti contoh HOL, yaitu Sepatu Sneakers seharga Rp 299.000 dengan 15 unit dan Headphone Bluetooth seharga Rp 350.000 dengan 10 unit. Enam produk tambahan membuat halaman kedua, filter stok rendah, dan filter stok habis langsung dapat diuji.

SELECT c.name AS kategori, COUNT(p.id_product) AS jumlah_produk
FROM categories AS c
LEFT JOIN products AS p ON p.id_category = c.id_category
GROUP BY c.id_category, c.name
ORDER BY c.name;

Pada database baru, hasilnya Elektronik 2, Fashion 3, Gaya Hidup 2, dan Olahraga 1. Perintah ini dapat dijalankan pada MySQL client untuk membandingkan tabel dengan grafik di dashboard.

3.1 Memisahkan halaman baca dan tindakan perubahan

Method Rute Kegunaan
GET /admin/catalog-dashboard · /admin/inventory Statistik katalog dan pemantauan stok.
GET /admin/products · /admin/products/create · /admin/products/edit/{id} · /admin/products/{id} Daftar, formulir tambah/edit, dan detail produk.
POST /admin/products/store · /admin/products/update/{id} · /admin/products/delete/{id} Menyimpan, memperbarui, atau menghapus produk.
GET / POST /admin/categories dengan create, edit/{id}, store, update/{id}, delete/{id} Pola method dan aksi mengikuti CRUD produk.
POST /admin/products/{id}/images/{id_gambar}/primary · /admin/products/{id}/images/{id_gambar}/delete Menetapkan sampul atau menghapus satu gambar milik produk.
POST /admin/inventory/{id} Mengganti jumlah stok dengan pengecekan nilai sebelumnya.

Semua form yang mengubah data membawa token CSRF. Controller memeriksa nama, kategori yang benar-benar ada, batas harga, bilangan bulat untuk stok, dan nilai status. Input yang salah menghasilkan pesan pada form. View mengodekan karakter khusus agar masukan pengguna tampil sebagai teks.

3.2 Menangani upload, gambar utama, dan kegagalan simpan

Form produk memakai multipart/form-data dan images[]. JavaScript menampilkan preview. Server memeriksa ekstensi, MIME, isi gambar, dan ukuran sebelum menyimpan. Batas implementasi adalah enam gambar per produk dan 2 MiB per gambar. Nama file dibangkitkan secara acak.

Saat produk baru memiliki gambar pertama, aplikasi menandainya sebagai utama. Perubahan galeri mengunci baris produk di MySQL agar dua permintaan tidak memilih dua sampul sekaligus. Jika gambar utama dihapus, gambar tersisa dengan ID paling awal mengambil peran tersebut. Bila transaksi simpan gagal, file baru yang sudah ditulis ikut dibersihkan.

3.3 Pencarian, inventori, dan dashboard

Filter nama dan kategori bekerja bersama sebelum pagination lima produk per halaman. Kedua parameter dibawa ke tautan halaman berikutnya. Menu Inventori menampilkan seluruh produk, stok rendah 1–5 unit, atau stok habis 0 unit. Dashboard menghitung jumlah semua produk, kategori, produk tersedia, dan produk tidak tersedia. Katalog publik hanya menayangkan produk berstatus tersedia dan memakai gambar utama yang dipilih pengelola.

3.4 Mengikuti satu permintaan dari form sampai database

Saat tombol Simpan produk dipilih, form mengirim nama produk, kategori, harga, stok, status, deskripsi, dan berkas opsional. Router mengarahkannya ke ProductController::store. Setelah input lolos validasi, controller memanggil operasi penyimpanan berikut.

(new ProductCatalog())->save($id, $data, $this->request->getFileMultiple('images') ?? []);

Di dalam transaksi, model membuat baris produk. Untuk setiap file yang telah lolos pemeriksaan, aplikasi membuat nama acak dan menghubungkannya dengan ID produk. Berikut potongan yang menjalankan langkah tersebut.

$filename = bin2hex(random_bytes(16)) . '.' . $extension;
$file->move(FCPATH . 'uploads/products', $filename);
$written[] = $filename;
$this->images->insert([
    'id_product' => $id, 'image' => $filename, 'is_primary' => $count++ === 0 ? 1 : 0,
    'created_at' => date('Y-m-d H:i:s'),
]);

Pada saat daftar dibuka, query menggabungkan produk, kategorinya, dan satu gambar berstatus utama. Penggunaan left join untuk gambar membuat produk yang belum memiliki foto tetap dapat ditampilkan. Dua parameter pencarian kemudian diterapkan jika diisi.

$this->select('products.*, categories.name AS category_name, categories.slug AS category_slug, product_images.image AS cover')
    ->join('categories', 'categories.id_category = products.id_category')
    ->join('product_images', 'product_images.id_product = products.id_product AND product_images.is_primary = 1', 'left');
if ($q !== '') {
    $this->like('products.name', $q);
}
if ($category !== '') {
    $this->where('categories.slug', $category);
}

Implementasi lengkap tersedia pada ProductController.php, ProductCatalog.php, dan ProductModel.php.

MySQL dan Chrome menyelesaikan 24 pemeriksaan, termasuk sepuluh skenario wajib serta pengujian keempat tugas pengembangan. Pemeriksaan terakhir menemukan dua foreign key, tidak ada produk bergambar dengan jumlah sampul yang keliru, serta jumlah data kembali ke 4 kategori, 8 produk, dan 8 gambar. Hasil pemeriksaan dalam JSON.

Contoh yang paling jelas terlihat saat harga dan sampul ransel diubah. Halaman detail, pencarian admin, dan katalog pelanggan menampilkan perubahan dari record yang sama. Uji hapus juga memperlihatkan dua perilaku berbeda yang dibutuhkan toko. Kategori terpakai dipertahankan, sementara gambar produk dibersihkan ketika produknya dihapus.
